Implemented

Two choices, one useful default

MRT/LRT exits and Bus stops only. A new search chooses the shortest usable saved walking route across both; a category click chooses within that category. Explicit saved-walk links retain their chosen stop and variant.

Closest means saved walking distance, not straight-line proximity. It does not mean every nearby stop has been routed. Stable ties and unavailable geometry are tested.

Implemented

No technical dump or comparison controls

SHIOK top left, search beneath, compact equal-width result. Destination and walk measurements first; uncovered sections and saved alternatives in Walk details. No Compare, About data, Technical record or score essay. Data information lives in GitHub README and attribution documentation.

Required basemap attribution remains. Old comparison fragments do not open or load a shortlist; stored data is not deleted.

Implemented

Preview failure cannot erase a saved walk

Reject failed HTTP responses and end a hanging preview after 12 seconds, including its response body. Keep the previous usable saved walk and marker visible. Retry makes one new request; Back restores the saved selection and URL. Ignore late responses.

Root cause found locally: the old QA proxy blocked every API request. The new proxy permits only GET /api/onemap-route. One public live request succeeded through the repaired API (HTTP 200, about 356 ms). This is an observed case, not an all-stop uptime promise. Stops without saved geometry still need a successful online preview.

Implemented

Automatic night lighting

No toggle. Load lamp-post data for the current neighbourhood when sufficiently zoomed in. Optional lamp failures do not block the selected walk. Do not download the entire island or label mapped lamps as a safety rating.

Remaining work, in practical order

Next acceptance

1. Finish the core walk on real devices

Validate postal entry, both categories, gap inspection, gestures, keyboard use and returning-user recovery on the exact current frontend. Next free work: simplify the transit popup, add a bounded server-side provider timeout (the current 12-second limit is client-side), and extend mixed-availability stop cases. Physical phone and owner task acceptance are still missing; headless viewport checks do not replace them.

Agent can fix bounded frontend issues now. Representative loading-time claims require a quieter host and controlled comparison. Zero pipeline cost.

Data gate

2. Name and close actual route-coverage gaps

A stop marker is not a saved walking route. Separate missing postal records, missing category choices, disconnected routes and missing geometry. The read-only 200-row pilot projected 9,111 seconds against a 900-second gate; no full register was run. Choose a smaller useful scope or explicitly approve a larger measurement before expansion.

Read-only diagnosis is distinct from data repair. New input, scoring or export work needs its own approval, versioned outputs and measured pilot. Existing data and weights stay untouched.

Owner decision

3. Make shelter reports a real service

Choose $0 storage/provider, privacy and retention, abuse limits, moderator and backup. Then implement two report types (incorrect mapping and missing shelter), location/section selection, a durable receipt and review status. There is no working submission service today.

T13 precedes T14-T18. No agency submission; never call a copied draft a submitted report.

Activation pending

4. Operate source checks and maintenance

Runbooks and source checks exist. Assign the review cadence and activate the approved scheduler and failure notices. Keep source-updated, last-checked and released dates distinct. Government publication speed does not excuse our own unreviewed queue.

Release gate

5. Approve and deploy an exact frontend release

Verify retained-runtime security/release identity, service-worker returning users, free-tier request budget, rollback and smoke tests. Deploy only after explicit release approval. Pushing main does not deploy while Git deployment is disabled.

Later

6. Any origin to any destination

Define route policy, coverage and cost after the postal-to-transit experience works. No live weather or agency workflow. Home comparison is removed and is not a prerequisite.

Only decisions that need the owner

  1. Physical-phone/task acceptance after the local checks.
  2. Report provider, privacy/retention, moderator and backup.
  3. Any expanded data-processing budget, operational activation and exact deployment.
